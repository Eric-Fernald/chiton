# Changelog

All notable changes to chiton are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project aims to follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- **`chiton serve` over stdio starts in a workspace that has no graph.** It used to exit with `no graph at …`, which an assistant shows only as chiton's tools being absent. The server now lists all 22 tools, and each call replies with the fix: run `chiton build .` (or the setup skill), then reconnect the server. Once a graph exists, the reply says to reconnect. `serve --http`, `serve --unix` and `serve --writable` are unchanged.

## [1.0.0] - 2026-11-24

The first public release.

### Added

- **The Claude Code plugin downloads the binary for the machine on first use.** The marketplace entry on `main` now points at a `plugin-dist` branch (`{"source": "github", "repo": "Eric-Fernald/chiton", "ref": "plugin-dist"}`). Each release (`.github/workflows/release.yml`, dispatched by hand with a tag) cross-compiles five binaries, publishes them with `checksums.txt` as a GitHub release, and pushes one commit to `plugin-dist`, parented on the previous release's so installed plugins fast-forward. That commit holds the assembled plugin, built by `scripts/build-plugin-dist.sh` (`make plugin-dist`): the manifest with `version` set to the tag, the skills, the `bin/` launchers, the install scripts, `release/tag` and `release/checksums.txt` pinning the release, and a `.mcp.json` that launches `${CLAUDE_PLUGIN_ROOT}/bin/chiton serve --stdio`. The branch carries no binaries. On first use the launcher downloads only this machine's binary (about 25 MB) from that release, verifies it against the `checksums.txt` shipped inside the plugin, and caches it in `~/.chiton/versions/<tag>/` (`%USERPROFILE%\.chiton\versions\<tag>\chiton.exe` on Windows); later launches use the cache, and a plugin update to a new tag downloads that tag's binary once. Old version directories are not cleaned up, and uninstalling the plugin leaves `~/.chiton/versions/` behind. Linux and darwin (amd64, arm64) and windows/amd64 are covered; Windows on arm64 gets the amd64 binary under emulation. The first MCP start waits for the download and can outlast Claude Code's MCP startup timeout on a slow link; reconnect with `/mcp` or `/reload-plugins` once it finishes. This download is a new automatic request to `github.com` and GitHub's release-asset CDN, listed in `docs/SECURITY.md` §1.1 and `docs/PRIVACY.md`. The repo-root `.mcp.json` still launches `chiton` by bare name for working on chiton itself (`claude --plugin-dir .`).
- **Privacy policy and plugin listing metadata.** `docs/PRIVACY.md` is new, and `.claude-plugin/plugin.json` now carries `license`, `icon` (`assets/icon.png`), `documentationUrl`, `supportUrl`, and `privacyPolicyUrl`.
- **Graph store layout version.** The Badger store now records its key layout under `m:schema`. Opening a store written by a newer chiton fails with an "upgrade chiton" error instead of misreading it, and an older layout is migrated on the first open (a read-only open does it through a one-time read-write pass). `.chiton/schema_version` is unchanged and still describes only the `.chiton/` scaffold.
- **`.chitonignore`.** A repo-root ignore file (names and globs, trailing `/` for directories, a leading or inner `/` anchors to the root, `!name` re-includes a built-in directory) now applies to `build`, `sync`, `sync watch`, `bench`, `analyze`, `analyze pending`, and the git hooks.
- **HNSW index for semantic search.** Large stores no longer scan every vector per query. `vector.index = auto` (the default) keeps the exact flat scan below 100k embeddings and switches to an HNSW graph at or above it; `flat` and `hnsw` force one. At 100k 768-dimensional vectors a query drops from about 30 ms to about 0.1 ms with recall@8 near 1.0 on embedding-like data. `chiton embed` builds the graph on every CPU and saves it beside the store as `hnsw.idx` (links only; the vectors stay in the store, and the file is encrypted when the store is). `serve` loads it in seconds instead of building at startup. When it is missing or out of date (embeddings changed since the last `chiton embed`), `serve` answers from the exact flat index at once, builds HNSW in the background, and switches over when it is ready, logging both steps. A one-shot `chiton search` stays exact under `auto`. Tune it with `vector.hnsw_threshold`, `vector.hnsw_m`, `vector.hnsw_ef_search`, and `vector.hnsw_ef_construction` (or `CHITON_VECTOR_*`). The graph is chiton's own pure-Go implementation (`internal/vector/hnswlib`); the default build stays cgo-free.
- **`chiton embed --link-similar --exact`.** `--link-similar` now uses the configured index, so large stores finish in minutes instead of an O(n²) scan; `--exact` restores the exact pass.
- **Claude Code plugin packaging.** `.claude-plugin/plugin.json` (`chiton`, version `1.0.0`; the release build stamps the tag's version) declares the plugin and `.claude-plugin/marketplace.json` a single-plugin marketplace (`chiton-marketplace`) that installs it from the `plugin-dist` branch. Both pass `claude plugin validate --strict` (`make plugin-validate` checks a clean clone). Load the plugin from a working tree with `claude --plugin-dir .`.
- **Three plugin skills**, namespaced `/chiton:graph`, `/chiton:subagent-tasks`, and `/chiton:setup`, living at `skills/{graph,subagent-tasks,setup}/SKILL.md`. `setup` is new: it walks a first-run workspace through locating or installing the binary, building the graph, and confirming the MCP server answers.
- **`skills/` is now the single source of truth for assistant-facing markdown.** A new root-level `embed.go` embeds each `SKILL.md` into the `chiton` package, and `internal/install/manifests` re-exports it, so the plugin and `chiton install` ship byte-identical text and cannot drift.
- **`chiton install` writes a second Claude Code skill.** Alongside `.claude/skills/chiton/SKILL.md` it now writes `.claude/skills/chiton-subagent-tasks/SKILL.md`; `chiton uninstall` and `chiton doctor` cover both. Skill frontmatter deliberately carries no `name:`, because the directory name supplies it in both the plugin and the installed layout.
- **`bin/chiton` and `bin/chiton.cmd` launchers.** The plugin puts `bin/` on the assistant's PATH, and the published plugin's `.mcp.json` starts the MCP server through the same launchers (Claude Code resolves `${CLAUDE_PLUGIN_ROOT}/bin/chiton` to `bin/chiton.cmd` on Windows). They resolve the real binary in order: `$CHITON_BIN`; then, in a published plugin, the cached binary for the pinned release, downloaded first if it is missing; then `chiton` / `chiton.exe` on PATH (skipping itself); then `$CLAUDE_PLUGIN_DATA/bin`; then `$HOME/.chiton/bin`. A failed download falls through to PATH, and a source checkout, which has no `release/tag`, skips straight to it. All their output goes to stderr, since stdout carries the MCP protocol. On failure they print install instructions instead of a bare "not found".
- **`scripts/install-chiton.sh` and `scripts/install-chiton.ps1`.** They download the release asset for the host OS/arch straight from the release download URL (`https://github.com/Eric-Fernald/chiton/releases/download/<tag>/`), verify its SHA-256 against a `checksums.txt`, and stop on any mismatch. They call no GitHub API and need no `gh`, `jq`, or token; `latest` resolves from the redirect of `https://github.com/Eric-Fernald/chiton/releases/latest`. `--checksums <file>` / `-Checksums` verifies against a local `checksums.txt` instead of the release's own (the plugin launchers pass the copy shipped in the plugin), and `--quiet` / `-Quiet` prints errors only. They install by copying beside the target and renaming over it. Nothing downloaded is executed by the scripts. Install location defaults to `$CLAUDE_PLUGIN_DATA/bin` under the plugin, otherwise `~/.chiton/bin`. Windows on arm64 gets the windows/amd64 binary. The POSIX script needs `curl` or `wget`, plus `sha256sum` or `shasum`.
- **`CHITON_PROJECT_DIR`.** When set, `internal/config` looks up `.chitonrc` in that directory and resolves a relative `graph_path` against it instead of against the process working directory. Unset, behaviour is unchanged. The plugin's MCP config sets it to `${CLAUDE_PROJECT_DIR}`.
- **New Makefile targets:** `build-msgraph`, `fmt`, `fmt-check`, `check-msgraph`, and `checksums`. `make release` now also writes `dist/checksums.txt`, which the install scripts require.
- **`.gitattributes`.** The tree is normalised LF-only, with CRLF kept for `*.cmd` / `*.bat` / `*.ps1` and explicit LF pins for `bin/chiton` and `scripts/*.sh` so the shim and installer survive being committed from Windows.
- **`SECURITY.md`, `CONTRIBUTING.md`, and this changelog** at the repository root. `SECURITY.md` is the private-reporting entry point GitHub surfaces; the threat model stays in `docs/SECURITY.md`.
- **Tests for the new surfaces:** `internal/config/config_test.go`, `cmd/chiton/netwarn_test.go`, a Teams webhook fail-closed test, and `internal/ingest/email/outlook_msgraph_test.go`.
- **`chiton bench` reports cheaper retrieval settings.** Each question now shows the depth-1 neighborhood and the `query_graph` lookup next to the depth-2 neighborhood.
- **Answer-quality benchmark.** `internal/bench/qualbench` asks Claude Code structural questions about a Go repository with grep only, with chiton added, and with chiton alone, and grades the answers against ground truth computed with `go/ast`. `gen -set hard` (the default) asks multi-hop questions: callers within 2 and 3 calls, callees within 2, and transitive imports and importers; `-set basic` asks direct ones. `report -regrade` re-scores stored replies. Results and method are in `docs/BENCHMARK.md`.
- **`package_deps` MCP tool.** It answers "what does package P import?" and "what imports P?" in one call by joining the `IMPORTS` of every file in a Go package. `package` takes a directory relative to the module root (`internal/graph/store`, `.` for the root), an import path, or a unique trailing part; `direction` is `imports` (default) or `importers`; `transitive: true` follows the chain and reports each package's depth; `include_external: true` adds standard-library and third-party imports. Only non-test files count by default; `include_tests: true` adds the imports of `_test.go` files and importers whose only importing files are tests. It is read-only and makes no network request. It needs a graph built by this version. Go file nodes now carry `import_path` and `module` attributes from the nearest `go.mod`.
- **`direction` and `exclude_tests` on `get_node_neighborhood`.** `direction: "in"` follows edges into each node (callers, importers, the containing file), `out` follows edges out of it (callees, imports, contents), and `both` (the default) keeps the old behaviour. `direction: "in"` with `edge_kinds: ["CALLS"]` lists a function's callers. `exclude_tests: true` leaves out nodes from `_test.go` files and does not walk through them.
- **`"<dir>:<Name>"` labels and an ambiguity note.** `get_node` and `get_node_neighborhood` accept a label such as `internal/analyze:New` or `internal/mcp:Server.Close`, naming the symbol in that package directory. When other symbols share the resolved name, their results carry a `note` field that says how many and how to pick another.
- **`chiton verify` re-checks inferred claims.** `chiton verify sweep` demotes concepts that no source backs any more to `AMBIGUOUS`, and re-links decisions whose governed symbol moved files. It lists a name that several symbols share instead of guessing, and it calls no LLM. `chiton verify pending` emits subagent tasks for the claims whose evidence changed. Each task checks a concept against the text of its sections, or a decision against the current source of a symbol it governs. `chiton verify submit` applies the verdicts. A `supported`, `revised` or `drifted` verdict must quote the evidence character for character, and a verdict below the confidence threshold is recorded without changing anything. Drift shows up in `decisions_about`. The same flow runs over MCP through the new `pending_verifications` and `submit_verification` tools, so the server registers 22 tools, 17 of them read-only.

### Changed

- **chiton is now licensed under the PolyForm Strict License 1.0.0 with an additional permission for commercial use** (previously proprietary with all rights reserved), and the repository is public. Anyone may use chiton for any purpose and install or build it by any documented route (plugin install, the install scripts, `go install`, `make build`); plugin marketplaces and mirrors may host unmodified copies. Otherwise distributing it and making changes or new works based on it remain reserved, so pull requests are not accepted. `go install github.com/Eric-Fernald/chiton/cmd/chiton@latest` works without `GOPRIVATE` or git credentials, and the install scripts need no credentials.
- **The MCP server advertises the binary's version** (`chiton version --short` without the leading `v`) instead of a hard-coded `0.1.0`.
- **Opening an unencrypted store prints a one-line notice** (`CHITON_PLAINTEXT_OK=1` hides it), and **`chiton-out/` now gets its own `.gitignore`.**
- **`chiton cluster` computes betweenness on up to 8 cores.** Brandes pivots are summed in fixed chunks of 32 on private buffers and added in chunk order, so scores are bit-identical on any core count; a full pass over a 118k-node graph dropped from 4.3 s to 0.95 s of compute.
- **The Badger value log is capped at 64 MiB per file** (Badger preallocates 128 MiB instead of 2 GiB while a writer is open), and a writable store runs a bounded value-log GC on close.
- **Label lookups on a read-only store** (`get_node`, `query_graph`, `shortest_path`, `chiton query`) answer from an in-memory label index after the first search instead of decoding every node.
- **`get_node_neighborhood` takes `max_nodes`/`max_tokens`** (defaults 100 / 4000) and reports `truncated`; all MCP tool results are compact JSON (no indentation or HTML escaping). `god_nodes` clamps `limit` to 1-100.
- **`graph_summary` counts kinds from the store's kind index,** and `search_meetings`/`decisions_about` read DECIDED_IN edges per decision (memoised on a read-only server) instead of decoding the whole graph on every call.
- **`chiton embed` no longer embeds label-only external package stubs, and the next run prunes their vectors**; this cuts `serve` memory on large Go graphs. The in-memory vector index stores all vectors in one contiguous slab.
- **Stored embeddings record their model and a hash of the embedded text.** `chiton embed` re-embeds nodes whose text or model changed and prunes vectors of deleted nodes, and `serve`/`search` exclude vectors from a different model with a warning. Existing vectors read as 'unknown model', so the first `chiton embed` after upgrading re-embeds them once. The hash embedder's model id now includes its dimension (`hash-256`), so changing `embed.dim` re-embeds instead of mixing vector sizes.
- **The missing-passphrase error now says how to fix it for an assistant**, and `chiton init` warns that an assistant-launched `serve --stdio` needs `CHITON_PASSPHRASE`.
- **Fewer duplicate writes.** The Go extractor emits each node and edge once per file, and a `build`/`sync once` run writes each shared `pkg://` stub once; `build`'s node and edge counts drop accordingly.
- **`shortest_path` walks adjacency keys** and decodes only the edges on the returned path.
- **Incremental sync no longer rescans the whole graph per file.** The Badger store keeps source_uri and kind indexes (store layout v2), so `DeleteBySourceURI` and kind or source filters read only matching nodes. The first open after upgrading builds the indexes once, and an open after an unclean shutdown rebuilds them. `store.CountByKind` counts nodes and edges from keys alone.
- **The pre-commit hook now gates the commit, not the working tree.** It analyzes the staged blobs of the committed files in memory, with file rules only, since graph rules need the whole corpus; pre-push still scans the tree. Neither needs the graph store any more, and findings are recorded only when the store opens without prompting.
- **One ignore list for every walk.** `build`, `sync`, `sync watch`, `bench`, `analyze`, `analyze pending`, and the git hooks skip `.git`, `.hg`, `.svn`, `.chiton`, `chiton-out`, `node_modules`, `vendor`, `.venv`, `venv`, `__pycache__`, `target`, and `dist` at any depth, plus the entries in `.chitonignore`; `bench` previously skipped nothing. `analyze` also no longer follows symlinks.
- **Live sync with `--analyze` is linear again.** Re-analyzing a file used to load and decode every deterministic finding in the store to prune that file's; it now reads the file's findings through their AFFECTS edges before replacing its nodes, and an Analyzer writes each rule node once. `sync once` over Go's `src/net` (390 files) dropped from 10.1 s to 3.4 s.
- **`chiton serve` with no transport flag now speaks stdio** instead of starting the HTTP/SSE daemon on 127.0.0.1:7474. Pass `--http 127.0.0.1:7474` for the daemon; `--stdio` is still accepted.
- **Microsoft Graph is now behind the `msgraph` build tag, and the default build excludes it.** The Graph SDK links request builders for every top-level Graph resource and kiota registers its serialization types through interface tables, so the linker cannot strip the parts chiton never calls. That came to about 117 MB of binary for two API calls. Excluding it took the stripped binary from **142.0 MB to 24.6 MB (-82.6%)**.
  - Affected commands: `chiton teams fetch`, `chiton teams serve-webhook`, and `chiton email outlook`. They still appear in `--help` and still parse their flags, but fail at runtime with a message telling you to rebuild with `-tags msgraph` (`make build-msgraph`).
  - `chiton email ingest` and `chiton email gmail` are pure Go and unaffected.
  - **Release artifacts are deliberately built without the tag.** If you rely on Teams or Outlook ingest, build your own binary with `make build-msgraph`.
  - `make check-msgraph` keeps the tagged path compiling and passing, since the default `make check` never compiles those files.
- **Git 2.30 or newer is required.** `sync git` (and so the post-commit/post-checkout hooks), `analyze --diff` and `diff_findings` pass `--end-of-options` to git, which older versions reject.
- **`make check` is now `fmt-check + vet + test`** (previously `vet + test`), so a non-gofmt-clean tree fails the pre-merge gate.
- **The root `.mcp.json` is now portable.** It launches `chiton serve --stdio` by bare name, so the binary must be on PATH, and it passes `CHITON_PROJECT_DIR=${CLAUDE_PROJECT_DIR}`. It previously hard-coded an absolute Windows path to `chiton.exe` and a `CHITON_GRAPH_PATH`. It serves source checkouts (`claude --plugin-dir .`); the published plugin uses `packaging/plugin/.mcp.json` instead. Anyone developing chiton itself should register their own build with `claude mcp add` at local scope rather than editing this file.
- **The always-on rules block written into `CLAUDE.md` / `AGENTS.md` and friends was rewritten.** It now names `semantic_search`, `get_node`, `diff_findings`, `search_meetings`, and `decisions_about`, explains `EXTRACTED` vs `INFERRED` vs `AMBIGUOUS` provenance, states that graph content (docs, transcripts, emails, page titles) is untrusted data rather than instructions, and mentions that the `pending_*` / `submit_*` flows need a writable server.
- **`internal/install/manifests/SKILL.md` was removed;** the package now re-exports the embedded content from `skills/` instead of holding its own copy.
- **The wildcard-bind warning used by `chiton serve --http` moved into a shared `warnIfNonLoopback` helper** (`cmd/chiton/netwarn.go`) so every listener warns the same way. It recognises an empty host and the unspecified IPv4/IPv6 addresses, and leaves named hosts alone rather than resolving them at startup.
- **Help text for `chiton teams` and `chiton email outlook`** now states the `-tags msgraph` build requirement up front.
- **The Outlook test whose subject takes a Microsoft Graph type moved behind the `msgraph` tag,** so the default test binary no longer links the Graph SDK.
- **Incremental re-clustering reads only the touched region.** `sync` used to load every node and edge and expand two hops through shared package stubs such as `pkg://fmt` on each re-cluster; it now reads the region through the store's neighbour index and treats stubs as leaves. A one-file edit on a 118k-node graph went from ~1.9 s to ~0.55 s. `cluster.json` is now compact JSON (about 20% smaller); older indented files still load.
- **`chiton bench` no longer picks test symbols as query targets.** Busy test helpers dominated the old sample; `--include-tests` restores it. Test files still count toward the corpus.
- **`chiton bench` costs what the server returns, and grep as `grep -w`.** Neighborhoods now include callers resolved across files and packages, as `get_node_neighborhood` returns them. The grep+read baseline matches the identifier as a whole word, so `Open` no longer also reads every file mentioning `OpenReadOnly`.
- **Go `CALLS` edges resolve across files and packages.** A bare call into a sibling file of the same package now produces a `CALLS` edge to the package's `pkg://` reference instead of being dropped, and `get_node_neighborhood` treats a function and the reference that callers in other files point at as one node, and reports it as the definition. "Who calls X" now finds callers in every file and package, and a multi-hop walk continues past package boundaries. The extractor no longer takes builtins and local names for calls, or mistakes a local variable that shadows an import alias for a package call. Rebuild the graph with `chiton build .` to get the new edges.
- **Label lookup ranks exact names first.** `get_node`, `get_node_neighborhood`, and `chiton query` rank a matching `file` hint first, then exact label matches (case-sensitive before case-insensitive), then labels ending in a `.` followed by the name, then other substrings, with definitions before files and files before external references. `New` no longer resolves to `NewEngine`, and a symbol named `fetch` no longer loses to the file `fetchall.go`.
- **The install rules block and the graph skill give call and dependency recipes.** The always-on rules prompt that `chiton install` appends and `skills/graph/SKILL.md` now say how to ask for callers, callees, call chains, and package imports, and when to use the `"<dir>:<Name>"` form. The skill's known limitations now describe what `CALLS` edges cover instead of the old substring caveats.

### Fixed

- **Graph-rule findings and report community listings no longer reorder between runs.** `god-module` and `circular-import` iterated maps, and the report broke betweenness ties only by source URI, which every symbol in a file shares.
- **`architecture/circular-import` can fire again.** Every extracted import points at an external package node, which the rule skipped, so it never reported anything on a real graph. It now resolves JS/TS and Python relative imports back to the scanned file they name. Go is excluded, because `go build` already rejects import cycles.
- **`chiton build` no longer skips files the graph store never received.** `cache.json` now records the store's random epoch, and entries written for another store (for example after the store directory was deleted) are discarded, with a stderr note that every file will be re-extracted. Build and sync also make the store's writes durable before saving the cache. Existing caches predate the epoch and are discarded once.
- **`chiton slack serve-events` and `chiton teams serve-webhook` ack before ingesting,** so slow ingests no longer trigger Slack/Graph retries and duplicate re-ingests. Bursts coalesce per conversation or meeting, and Slack redeliveries are dropped by `event_id`. The Slack and Gmail clients retry HTTP 429 using `Retry-After`.
- **A mistyped passphrase no longer creates a store you cannot reopen.** `chiton init` now stores a passphrase verifier in `keyfile.json`, and every command checks it. Older keyfiles are upgraded on their next successful open.
- **`.chiton/` state now follows `CHITON_PROJECT_DIR`.** An assistant-launched server started outside the workspace read `diff_findings` baselines, resolved their git refs, and wrote LLM-rule state relative to its own working directory.
- **A malformed `.chitonrc` is now an error.** It used to be ignored, so a typo silently dropped `graph_path` back to the default and the command opened a different store.
- **`sync watch` recovers from event overflow.** When fsnotify reports dropped events, the watcher rescans the tree instead of silently missing changes.
- **`chiton build` runs the sync engine.** It removes symbols renamed or deleted since the last build, prunes files gone from disk along with their findings (`--prune`, default true; `sync` without `--analyze` now drops a deleted file's findings too), skips ignored directories and `.chitonignore` paths, extracts on `GOMAXPROCS` workers, and batches store writes. The summary line is unchanged; per-file skip messages on stderr now start with `sync: skip`.
- **Windows path case no longer duplicates files.** `file://` URIs use an upper-case drive letter and on-disk case, so `chiton build c:\repo` and `chiton build .` index one copy. The next `build`/`sync once` drops entries an older build stored under a different case (those files are re-indexed once). On Windows, `file://` URIs also resolve symlinked or junction directory components, so files under a linked ancestor directory are re-indexed once under the resolved path.
- **`sync once` survives unreadable directories and honours Ctrl-C.** A permission error below the root is logged and counted (`N unreadable` in the summary) instead of aborting the run, and `sync git`/`sync once` stop between files when cancelled.
- **Re-syncing a file no longer deletes meeting and concept links.** File sync and meeting/Slack/Teams/URL/email re-ingest replace a source by diff. Nodes the new extraction drops are deleted with their edges, but edges other sources attached to surviving nodes (`DECIDED_IN`, `DISCUSSED_IN`, `MENTIONED`, concept `DESCRIBES`, finding `AFFECTS`) are kept. An unchanged node keeps its `extraction_status` and embedding; a changed one loses its embedding so `chiton embed` redoes it. Decision and rationale nodes now use `decision://<meeting-uri>`, so re-ingesting a Slack channel no longer deletes them; older ones move on the next re-ingest.
- **The graph store no longer wedges with "Log truncate required".** On Windows, a writer opened while `chiton serve` had the store mapped could fail halfway and strand a 128 MiB memtable log that broke every later read-only open. chiton processes now coordinate on `chiton.lock` in the store directory and fail fast with `graph store is in use by another chiton process` instead of colliding. On Windows a writer is refused while any reader is open; on Linux/macOS writers may still open beside a read-only server. A read-only open now replays a crashed writer's log itself when nothing else holds the store.
- **Leiden no longer collapses the graph into a few giant communities.** Aggregation dropped each community's internal weight from the super-node degree and the total, so every merge looked profitable, and each level restarted from singletons instead of the unrefined partition. On this repo's graph the largest community fell from 87.5% of nodes to 15%, and Zachary's karate club now scores Q ≈ 0.42 (was 0). Re-run `chiton cluster` to refresh `cluster.json`.
- **Git hooks no longer block commits on infrastructure errors.** A locked store (a running `sync watch`), an encrypted store with no passphrase, a git error, or a malformed `hooks.yaml` used to fail `git commit`, and a failing `sync git --stage …` also failed `git checkout`. These now warn and exit 0. `timeout-seconds` is enforced (the analyzer checks its context per file and per graph rule), and an unreadable directory is skipped and counted instead of aborting `chiton analyze` or `analyze pending`.
- **An assistant-launched MCP server no longer risks reading a different store than `chiton build` wrote.** MCP servers are not reliably started in the workspace root, and the default `graph_path` is relative, so a server started elsewhere would resolve it against its own working directory and answer from an empty graph. `CHITON_PROJECT_DIR` (set by the plugin) now anchors both the `.chitonrc` lookup and relative `graph_path` resolution.
- **Live sync now prunes removed directories on Linux.** `fswatch` decided whether a removed path had been a directory by consulting fsnotify's `WatchList()`. On Linux fsnotify drops a deleted directory's watch from that list *while draining the kernel's event buffer*. It processes `IN_DELETE_SELF` and `IN_IGNORED` before the parent's `Remove` event reaches the Events channel, so by the time the watcher handled the event, the path was already gone from the list. The removal was misread as a file event, `OnDirRemove` never fired, and `chiton sync watch` left every node under the deleted directory in the graph. The watcher now tracks the directories it watches itself, which is unaffected by fsnotify's internal timing. Windows was never affected, which is why this only surfaced in CI.
- **`CHITON_EMBED_DIM` is no longer silently ignored.** `embed.dim` is the one setting with no default, so it never entered viper's key set and `Unmarshal` skipped it. The variable parsed fine and then did nothing. It is now bound explicitly, and a value in `.chitonrc` still works as before.
- **The job queue no longer drops a change that arrives just after a run.** A debounce timer's entry stayed in place until after its key had been handed to a worker. If the run finished first, the next enqueue of that key took the stale entry to mean a run was still coming and did nothing. `chiton sync watch`, `chiton browser watch`, and the Slack and Teams receivers could therefore miss a file save or a message until the same file or conversation changed again.

### Security

- **The cluster sidecar is encrypted for encrypted stores.** `cluster.json` held every node label and source URI in plaintext; it is now sealed with a key derived from the store key. Existing plaintext sidecars load and are sealed on their next write.
- **Webhook secrets no longer go on the command line.** `--signing-secret` and `--client-state` are removed and now fail with a pointer to `--signing-secret-file` / `--client-state-file`, which read the secret from a file (a leading UTF-8 BOM, as PowerShell 5.1 writes, is stripped). The `CHITON_SLACK_SIGNING_SECRET` and `CHITON_TEAMS_CLIENT_STATE` env vars work as before.
- **`chiton install`/`uninstall` no longer reset MCP config files to 0644 or replace symlinks.** Files such as `~/.codex/config.toml` keep their existing mode, a symlinked config is written through, and new MCP configs are created 0600.
- **`chiton browser ingest|watch` strips userinfo, query strings and fragments from history URLs** (they carried OAuth codes, reset tokens and presigned signatures into every MCP read tool). Rows that then share a URL merge, and pages stored unredacted by an earlier ingest are deleted on the next run. `--keep-query` restores query and fragment.
- **`chiton serve --unix` creates its socket owner-only (`0600`).** Its mode used to follow the umask, which could let group members or every local user read the graph.
- **A repository's `.chitonrc` can no longer send your text off-device.** A non-loopback `embed.endpoint` set by the project `.chitonrc` is refused. Set `CHITON_EMBED_ENDPOINT` yourself to use a remote embedder.
- **The graph tools redact people by default.** `get_node`, `query_graph`, `get_node_neighborhood`, `shortest_path`, `semantic_search`, `god_nodes` and `graph_summary` now redact people's names, email addresses, speakers and assignees by default; `chiton serve --include-pii` restores them.
- **`submit_extraction` rejects a `task_id` that isn't a doc_section or image** and no longer overwrites concepts other tasks created, so a forged submit can't mark meetings as linked or rewrite concept descriptions.
- **`diff_findings` baseline/target refs are validated** and passed to `git rev-parse --verify --end-of-options`, so an option-like ref such as `--show-toplevel` can no longer leak the repository path.
- **`add_url`'s SSRF guard now checks the IP it actually dials** (closing the DNS-rebinding race) and blocks CGNAT, benchmarking, reserved, multicast, NAT64/6to4/Teredo, IPv4-mapped, IPv4-compatible and SIIT ranges; `add_url` no longer goes through `HTTP(S)_PROXY`.
- **Indexing no longer follows symlinks.** `build`, `sync`, and `sync watch` index regular files only; a symlink or junction (e.g. `notes.md -> ~/.ssh/id_rsa`) is skipped, so its target never lands in the graph or in `pending_extractions`.
- **MCP `add_url` accepts only http/https URLs** (the CLI still reads local files), and `pending_analyses` refuses paths outside the project root and no longer reads through symlinks, so an injected instruction can't make an MCP tool read `~/.aws/credentials`.
- **`chiton serve --http` now requires a bearer token** (per start, written to `<graph dir>/mcp-token`, or `CHITON_MCP_TOKEN`), refuses browser `Origin`s not listed with `--allow-origin`, requires `application/json` POSTs, and no longer sends `Access-Control-Allow-Origin: *`. Before this, any web page could call tools on the loopback server with a `text/plain` POST.
- **`chiton teams serve-webhook` now fails closed.** Two changes, both behaviour-visible:
  - The command **refuses to start** without a subscription `clientState` (`CHITON_TEAMS_CLIENT_STATE` or `--client-state-file`), rather than starting a receiver that cannot authenticate anything.
  - The handler itself now **rejects every notification** when no `clientState` is configured. It previously accepted them all and trusted any caller, so any host that could reach the port could inject forged meeting content into the graph.
  - If you were running the webhook receiver without `CHITON_TEAMS_CLIENT_STATE` set, it will now exit with an error until you configure the shared secret you registered with the Graph subscription.
- **Webhook and events listeners now default to loopback.** `chiton teams serve-webhook` defaults to `127.0.0.1:8444` and `chiton slack serve-events` to `127.0.0.1:8445`; both previously defaulted to `:8444` / `:8445`, which binds **every** network interface. Both commands now also print a warning when the configured address is a wildcard. Neither receiver is meant to face the internet directly. Put a tunnel or reverse proxy in front. If you depended on the old wide bind, pass `--addr 0.0.0.0:<port>` explicitly and heed the warning.
